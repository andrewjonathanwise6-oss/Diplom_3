# Diplom_3: Stellar Burgers

Автоматизированные UI тесты веб приложения Stellar Burgers для дипломного задания Яндекс Практикума.

Используются Python, Selenium, pytest, requests и Allure.

Реализовано 17 тестовых сценариев. Каждый сценарий проверяется в Google Chrome и Mozilla Firefox.

## Установка

Для запуска необходимы Python, Google Chrome и Mozilla Firefox.

Создать виртуальное окружение:

`python -m venv .venv`

Установить зависимости:

`.\.venv\Scripts\python.exe -m pip install -r requirements.txt`

## Запуск тестов

Запуск всех тестов в двух браузерах:

`.\.venv\Scripts\python.exe -m pytest --browser all`

Запуск только в Chrome:

`.\.venv\Scripts\python.exe -m pytest --browser chrome`

Запуск только в Firefox:

`.\.venv\Scripts\python.exe -m pytest --browser firefox`

## Allure

Запуск тестов с сохранением результатов Allure:

`.\.venv\Scripts\python.exe -m pytest --browser all --alluredir=target/allure-results --clean-alluredir`

Просмотр отчёта:

`allure serve target/allure-results`

## Проверяемая функциональность

**Восстановление пароля**

Переход к восстановлению пароля, заполнение формы и проверка активации поля пароля при нажатии на значок.

**Личный кабинет**

Переход в личный кабинет, просмотр истории заказов и выход из аккаунта.

**Конструктор**

Переход между конструктором и лентой заказов, просмотр деталей ингредиентов, закрытие модального окна, добавление ингредиентов и оформление заказа.

**Лента заказов**

Просмотр деталей заказа, отображение заказа пользователя в общей ленте, обновление счётчиков выполненных заказов и появление номера нового заказа в разделе «В работе».

## Структура проекта

`tests/` содержит автоматизированные тесты, разделённые по функциональности.

`pages/` содержит классы Page Object для взаимодействия со страницами.

`locators/` содержит локаторы элементов интерфейса.

`helpers/` содержит вспомогательные методы для работы с API.

`conftest.py` содержит фикстуры браузеров и тестовых пользователей.

`requirements.txt` содержит зависимости проекта.

## Тестовые данные

Для тестов, которым необходим пользователь, аккаунт создаётся через API перед выполнением сценария.

После теста временный пользователь удаляется.

Тесты независимы друг от друга.

## Особенности

В Chrome для добавления ингредиентов используется Selenium ActionChains.

В Firefox используется отдельная реализация через HTML5 DragEvent, поскольку обычное перетаскивание в проверенной версии Firefox не завершалось событием drop. Этот способ проверяет обработку добавления ингредиента приложением.

В сценарии восстановления пароля проверяется активация и подсветка поля после нажатия на значок. На тестовом стенде также обнаружена проблема с повторным скрытием пароля.
