# Diplom_3 — Stellar Burgers

UI-тесты дипломного задания Яндекс Практикума: 17 независимых функциональных
сценариев, каждый выполняется в Chrome и Firefox (34 теста).

Последний полный прогон 30.10.2026 после уточнения сценария №3:
**34 passed** за 319.62 секунды. В каждом браузере — 17 passed, падений нет.
Ошибок setup/teardown нет, все 20 пользователей итогового прогона удалены.
Подробные результаты и список файлов: [docs/validation.md](docs/validation.md).

## Установка

Нужны Python 3.10+, установленные Chrome и Firefox и доступ к учебному стенду.
Зависимости закреплены в `requirements.txt`; проверенное окружение — Python 3.14.
Selenium Manager находит или скачивает совместимые драйверы при первом запуске.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

По умолчанию используется `https://qa-stellarburgers.education-services.ru`.
Другой адрес можно задать через `$env:STELLAR_BASE_URL` до запуска pytest.

## Запуск

Полный последовательный прогон обоих браузеров с новым набором Allure-результатов:

```powershell
$env:PYTHONIOENCODING = 'utf-8'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
.\.venv\Scripts\python.exe -m pytest --browser all --tb=short -v --alluredir=target/allure-results --clean-alluredir 2>&1 | Tee-Object -FilePath "$env:TEMP\pytest_last.log"
$testExitCode = $LASTEXITCODE
Write-Output "pytest exit code: $testExitCode"
```

Лог сохраняется в `%TEMP%\pytest_last.log` (`$env:TEMP\pytest_last.log` в PowerShell).
Код завершения pytest необходимо проверять отдельно: последняя команда конвейера —
`Tee-Object`. Результаты не следует смешивать с диагностическими прогонами.

Отдельный браузер или сценарий:

```powershell
.\.venv\Scripts\python.exe -m pytest --browser firefox --tb=short -v --alluredir=target/firefox-results 2>&1 | Tee-Object -FilePath "$env:TEMP\pytest_last.log"
.\.venv\Scripts\python.exe -m pytest tests/test_constructor.py --browser chrome --tb=short -v 2>&1 | Tee-Object -FilePath "$env:TEMP\pytest_last.log"
```

Для запуска без окна добавьте `--headless`. Основной проверяемый режим — обычный
браузер с окном размером 1440 × 900. Параллельный запуск не настроен.

## Allure

При падении в setup, test call или очистке пользователя прикладываются PNG-скриншот и текущий URL,
если браузер уже создан и доступен. Ошибка снятия скриншота не скрывает исходное
падение. В отчёт также попадают версии браузеров и результаты удаления пользователей.

При установленном Allure CLI:

```powershell
allure generate target/allure-results --clean -o target/allure-report
allure open target/allure-report
```

`target/`, логи, окружение и настройки IDE исключены из Git.

## Архитектура и данные

- `pages/`: отдельные Page Object конструктора, ленты, авторизации, личного кабинета,
  истории, запроса восстановления и сброса пароля; компонент модального окна ингредиента.
- `locators/`: все CSS/XPath локаторы отдельно от действий и тестов.
- `helpers/api_client.py`: создание и удаление временных пользователей.
- `conftest.py`: браузеры, независимые пользователи, UI-авторизация, очистка, Allure.
- `tests/`: действия и явные проверки результата сценария.
- `docs/api.md`: исследованные API и источники контракта.

Для каждого теста, которому нужен аккаунт, создаётся уникальный пользователь через API.
Финализатор удаления регистрируется до запроса создания и выполняется при падении
подготовки или теста. Ошибка удаления становится ошибкой teardown, а не скрывается.
Постоянные аккаунты не используются. Авторизация и оформление заказов выполняются
через интерфейс; API не подменяет проверяемые пользовательские действия.

Восстановление проверяется до формы ввода кода: чтение почты и фактическая смена
пароля по коду не входят в эти 17 требований. Почта принадлежит временному аккаунту.

## Drag-and-drop и ограничение Firefox

Настоящая область приёма — `section` с `BurgerConstructor_basket__`, к которому
фронтенд подключает React DnD `dropTarget`. В Chrome используется нативный
`ActionChains.drag_and_drop`.

В Firefox 159.0 / geckodriver 0.37.1 / Selenium 4.52.0 проверены нативное
перетаскивание на настоящий target и захват текста вместо картинки. В обоих
случаях получен `dragstart`, но нет `drop`/`dragend`, счётчик остаётся 0.

Поэтому только для Firefox внутри `ConstructorPage` изолирован HTML5-обход:
`dragstart → dragenter → dragover → drop → dragend` с общим `DataTransfer`.
Он проверяет обработчики приложения, **не физический жест мышью**. Состояние Redux,
счётчик и ответы сервера напрямую не изменяются. В Allure этот способ отмечен
отдельным шагом; автоматического скрытого fallback после падения проверки нет.

Ожидания реализованы через `WebDriverWait`; `time.sleep`, `skip` и `xfail` не используются.

## Известный дефект приложения: скрытие пароля

В исследованной версии стенда повторное нажатие значка скрытия оставляет
`type=text` вместо `type=password`.

Причина подтверждена в опубликованной карте исходников
[`password-input.js`](https://qa-stellarburgers.education-services.ru/static/js/2.6a70b014.chunk.js.map)
из пакета `@ya.praktikum/react-developer-burger-ui-components`: `onIconClick`
всегда устанавливает `visible=true`, `visible=false` устанавливается при `blur`.
Это код удалённого приложения, которого нет в данном репозитории с тестами.

По уточнённому пользователем требованию сценарий №3 проверяет активацию
и подсветку поля после клика по значку. До клика поле не в фокусе и не подсвечено;
после клика проверяются фокус и класс активного поля. Повторное скрытие не входит
в согласованный объём этой проверки. Это уточнение требования, а не skip/xfail.

Дефект повторного скрытия остаётся отдельным наблюдением о приложении.
Результаты предыдущего прогона с дополнительной проверкой, включая оба падения
и скриншоты, сохранены в `target/password-toggle-investigation/allure-results`,
лог — в `target/password-toggle-investigation/pytest_last.log`.
